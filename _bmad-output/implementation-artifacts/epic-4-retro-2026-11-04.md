   - Upstream lesson: the planning copy assumed a hold the content does not use, so check UX copy against the authored content before story creation.
2. **`TEST_ME` and `ADAPTIVE_ASSISTANCE` are still OFF in release.**
   - `FeatureFlagLevels.kt:16` sets every flag OFF for `release` and `benchmark`, and its KDoc says "release raises each flag in its own feature story" (`:19`).

   - Debug is GA for every flag, so the 4.6 beta label (`AssistanceLine.kt:32`, `spec-4-6-…md:205`) is never visible in any build type.

It was a recorded PO decision inside AD-6's registry rules.

### Cross-story boundaries (inline code lens)

4. **Following a Guided recovery plan can count as adaptive-assistance mistakes (4.5 × 4.6).**
   - In `Reduce.kt:162-171`, `committed` classifies the Move and calls `adapted(... harmful = assessment?.feedback == HARMFUL)` before it checks whether the Move is the next Move of a `GuidedRecovery.Planned`. A plan Move is never exempted.
   - 4.5 itself records that "Following a multi-Move plan may still show a Diagnosis on an intermediate Move" (`spec-4-5-…md`, Residual risks).
   - So a Learner who follows the tutor's own correction can raise `stepMistakes` and escalate assistance. No test covers the combination: `AdaptiveAssistanceSessionTest.kt` has no plan-following case, and `GuidedRecoverySessionTest.kt` has no adaptive case.
   - Severity: medium. This was derived from reading the code, not from running it.
   - Disposition: **fix now** → action item 4.
5. **The auto-demonstration replays after the Lesson is closed and reopened (4.6).** The Codex gate passed round 4 with this medium open (ledger `GATE 4-6 PASS round4 … auto-demo replays after close/reopen, LessonScreen.kt:218`). The `demonstrated` set is `remember(lesson.id)` composition state (`LessonScreen.kt:218`), so it is lost when the screen leaves composition. Disposition: **fix now** → action item 2.
6. **RecoveryPlanner's same-face pruning is incomplete for move-set subsets (4.5).**
   - The gate passed with this medium open (ledger `GATE 4-5 PASS round1 … findings=1medium`).
   - The cause is in `RecoveryPlanner.kt:93,150`: `redundant` drops any two consecutive turns of the same face. That is correct only when the move set holds all three turns of every face.
   - The shipped `tutor-config.json` holds all 18 face turns, so nothing is wrong today.
   - A related 4.1 residual: `maxDepth` 3 would turn one-move Diagnoses into LIKELY through commuting sequences (`spec-4-1-…md`, follow-up Residual risks). `tutor-config.json` allows that value.
   - Disposition: **defer with a guard** → action item 3.
