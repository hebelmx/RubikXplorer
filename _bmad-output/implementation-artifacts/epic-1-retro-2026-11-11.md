## Findings

Each finding has a disposition (fix now / defer / accept) and an upstream lesson.

### Spec-to-implementation reconciliation

**F1. CI gates are not enforced on `main` (Story 1.1 AC3 deferral never landed).** Story 1.1 deferred "Make the CI workflow a required status check on main" (`spec-1-1-…md:28-34`, severity medium). `gh api repos/hebelmx/RubikXplorer/branches/main/protection` returns `404 Branch not protected`; the only ruleset ("Kotlin", id 26292541) has `enforcement: disabled`; `rules/branches/main` is `[]`. Every Epic 1 PR did pass CI, but only because the orchestrator merges on all-green, and the platform does not enforce it. The AD-1/AD-13 portfolio claim "gates block merges" is therefore only true by convention. *Disposition:* fix now (a repo setting, owner PO). *Lesson:* a deferral that lives outside the diff (repo settings) needs a tracked action item. Nothing routed this one, which is the gap `epic-2-retro-item-1` (deferred-findings ledger, still open) describes.

**F2. The 2D net frame-timing benchmark measures the wrong screen and can pass with no data.** Since Epic 5 the Solve tab free cube is `Cube3DRenderer` on GL, so `Net2DFrameTimingBenchmark` (`macrobenchmark/src/main/kotlin/dev/cubentia/macrobenchmark/Net2DFrameTimingBenchmark.kt:17,40`, still documented as "the Solve tab's free cube (`Net2DRenderer`)") failed on the Tab S7 FE and "passed" on the S24 FE with `frameCount = 1` per iteration (`spec-1-11-…md:13-21`). `Net2DRenderer` is now used only by `SolutionPlayback.kt:82`. Story 1.11 AC1 was met by a PO waiver for v1.0 (issue #106, linked at `docs/benchmarks.md:155,195`). The benchmark itself is unchanged: there is still no minimum-frame-count check, and the deferral is not in `action_items`. Story 12.2 (performance and compatibility, the current branch) reuses these harnesses, so a vacuous pass can reach release evidence. *Disposition:* fix now (owner Dev, in or before 12.2). *Lesson:* a story that moves a screen to a new renderer (5.1/5.2) must re-point or retire the harnesses that measure that screen. This was a seam between two stories that no single story owned.

**F3. The architecture spine still credits the wrong story with the device measurement.** `ARCHITECTURE-SPINE.md:525` reads "Performance on the reference devices: Story 1.10 measures it". The measurement moved to 1.11 at the split (#26), with the full pass in 12.2. `epic-1-context.md` flags this as a "pending doc fix". The 2D-net NFR-2 baseline waiver (#106) is not recorded in the spine or the PRD either. *Disposition:* fix now via `bmad-architecture` update (the spine is `final` and may not be hand-edited). Owner: Architect. *Lesson:* a story split through correct-course should also sweep the spine for the story numbers it names.

**F4. FR-3's free cube is no longer a 2D net.** Story 1.6 delivered the free cube on `Net2DRenderer` (PR #9). Epic 5 replaced it with the 3D renderer, and `Net2DRenderer` survives only in solution playback (F2). Epic 1's stated outcome ("turn a cube on a 2D net with buttons") is superseded, not regressed: the 2D net remains for playback, and `FreeCubeScreen.kt`/`MoveKeyBar.kt` still ship buttons. *Disposition:* accept as-is (intended evolution through AD-4/Epic 5). F2 and F3 are the only consequences that need action. *Lesson:* none beyond F2.

**F5. The Story 1.9 spec status is stale.** `spec-1-9-…md:5` reads `status: 'built'` ("Status: built", line 107), while sprint-status says `done`. The spec's one deferral, the PRD memlog append for the BETA outcome, did land: `bc10794` added PRD `.memlog.md:42` (62.5% per sticker), and `.memlog.md:43-44` record the v1.1 camera deferral. *Disposition:* fix now (low; set the spec to `done`; owner SM). *Lesson:* the orchestrator's story-close step should set spec status together with sprint status.
