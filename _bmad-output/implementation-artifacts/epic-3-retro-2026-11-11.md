### Spec-to-implementation reconciliation

**F1. The Solve tab's preparing copy is untrue on the minimum device, and the planning text pins it.** `msg.solve.preparing` reads "Preparing the solver (one time, a few seconds)." (`core/domain/src/main/resources/content/strings/en.json:3`). Story 3.8 measured about 8 s per process start on the Tab S7 FE, almost all of it move-table construction (#104; `spec-3-8-…md:134`). The text is fixed word for word by the 3.7 AC (`epics.md:850`) and `EXPERIENCE.md:130`. The PO accepted the gap for 3.8 and deferred the speed-up to v1.1 (#104). Issue #112 (pre-release) covers rewording the copy for v1.0. *Disposition:* fix now, before release (#112). Because the AC and UX table quote the old string verbatim, the reword also needs a `bmad-correct-course` reconciliation of `epics.md:850` and `EXPERIENCE.md:130`; this run did not edit either. *Lesson:* Learner copy that makes a timing promise ("one time, a few seconds") should not be fixed in an AC before the device measurement that would prove it exists.

**F2. Story 12.2's release-equivalent run supersedes the zero-failure part of #105.** Story 3.8 recorded 1 device timeout in 10,101 (debug build, 3,000.9 ms) and 1 calibrated-profile failure (k = 16.94), accepted by PO waiver as #105 (`spec-3-8-…md:134,156`). Story 12.2 re-ran the same corpus (seed 20261031) on the `benchmark` build on the Tab S7 FE: 10,101/10,101 within 3 s, 0 failures, median 17.012 ms, p95 101.730 ms, max 1,074 ms (`docs/benchmarks.md:283-320`, `docs/evidence/12-2/solve-corpus-benchmark-build-tab-s7-fe.log`). The page itself states "this run had no failure to waive". #105 still describes a zero-failure miss as its problem. *Disposition:* fix now (low; issue hygiene, owner PO): narrow #105 to the release-equivalent recalibration of k and the slow-case investigation, citing the 12.2 result. *Lesson:* a waiver issue should be revisited when a later story produces stronger evidence for the same criterion.

**F3.
