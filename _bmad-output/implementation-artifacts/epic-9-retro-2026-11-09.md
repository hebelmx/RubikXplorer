### Cross-story review (bmad-review lenses: adversarial, edge-case-hunter, verification-gap)

The three lenses ran as parallel subagents over the code diff `ef09978..e6e4108` (excluding `_bmad-output/` and `app/schemas/`). Their findings were treated as unverified and re-checked against source before routing.

1. **A Course Lesson opened after LL practice runs as practice.** `LessonScreen.kt:253` sets `practicing = !isTwoLook && (isPractice || isSkipCheck || host.state.value.kind == SessionKind.PRACTICE)`. Closing practice only sets `openPractice = null` (`AppShell.kt:240, 280, 292, 389`) and never ends the host session. So after LL practice, live or restored on cold start (new in 9.8, `SessionHost.kt` restore of `PRACTICE_ID`), opening a Course Lesson dispatches `PracticeStarted`. The Lesson then runs with no Teaching Modes, and no `LessonCompleted` is written, because completion requires `kind.isTaught` (`SessionState.kt:211`). The `PRACTICE` term dates from Story 7.4. Story 9.7 (`d9b60f8`) edited this exact line to add `!isTwoLook`, and Story 9.8 added a new way to reach the state (cold-start restore). No test opens a Course Lesson while the host is `PRACTICE`. Found by both edge-case-hunter and verification-gap. **Fix now.**
2. **The 2-look offer can downgrade *Learned* to *Learning*.** `AppShell.kt:207` builds `notStarted` from `algorithmStatuses`, which is collected with an `emptyMap()` initial value. `RoomAlgorithmStatusRepository.kt:19-21` also emits `emptyMap()` on any upstream failure, and the flow then completes, so the Library shows every Algorithm as *Not started* for the rest of the run. In either state, *Add to Learning* (`AppShell.kt:228-229`) appends `LEARNING` over an Algorithm the Learner marked `LEARNED`, which breaks the 9.6 rule that Algorithm Status is the Learner's own judgment. Found by both adversarial and edge-case-hunter. **Fix now.**
3. **Continue reopens 2-look content after *Reset progress*.** `AppShell.kt:467-473` offers a Continue entry for any taught session (`TWO_LOOK`) or LL practice (`twoLookPracticeContinue`) without checking `allStagesFinished`. A reset does not end the live session, so locked 2-look content stays reachable, against the 9.7 unlock AC (FR-17). Found by both adversarial and edge-case-hunter. **Fix now.**
4. **`TRANSITIONS.md` is stale after the 9.8 acceptance-gate fix.** Line 223 says LL practice is "rebuilt from the snapshot's start cube", and line 272 says "No snapshot or checkpoint format changes". Commit `9e71566` added `SessionSnapshot.practiceEntry` and rebuilds from it. **Fix now** (documentation).
5. **The shell's choice of recognition diagram is untested.** `AppShell.kt:208-216` derives each 2-look Lesson's diagram from `lessonAlgorithms.firstOrNull()`. The only shell assertions are existence checks (`AppShellLibraryTest.kt:288, 309`). `LessonScreenTest` injects its own diagram, so a wrong lookup would pass every test. **Fix now** (test).
6. **2-look *Mastered* does not require *Completed*.** `TwoLookMastery.kt:36` sets `mastered = count >= solvesRequired` without `completed`. The epic context defines the two states separately, so this may be intended, but the row can read *Mastered* while 2-look Stage rows below it still show unfinished Lessons. **Defer** (open question for PM).
7. **The mastery judge is a second definition of "solved with an allowed Algorithm".** `TwoLookSolve.kt:21-40` compares exact cubie effects and applies its own U-turn rule. `LastLayerMatcher`, documented as the single definition of Case patterns and AUF (AD-19, epic context "One `LastLayerMatcher`"), is never constructed in production code; verification, diagram derivation and the 2-look predicates reach it only through tests and content-time derivation. The two rules can drift. Story 9.8 Design Notes record the choice as an intent reading made during the build, not a planning decision. **Defer** (spec reconciliation: architect to confirm or narrow AD-19).
8. **2-look Lesson prerequisites are validated but never applied.** `LearnScreen.kt:590` unlocks every Lesson when `courseControls` is false. All 16 shipped 2-look Lessons declare `"prerequisites": []`, so this is latent. **Defer.**
9. **A 2-look step may reference a non-primary Algorithm.** `TwoLook.kt:63` accepts any Algorithm ID, but the Library shows only `-a` primaries. All 16 shipped references are primaries (`alg-oll-02-a` … `alg-pll-z-a`), so this is latent. **Defer.**
10. **Low-severity robustness items.** Each is **defer**:
    - `AppShell.kt:256` writes `twoLookScramble` during composition inside a `remember` keyed on it.
    - `LessonScreen.kt:179` evaluates `TwoLookMastery` on every recomposition and passes `emptyList()` for stages.
    - `AlgorithmDetailScreen.kt:69`: the optimistic `RequestedAlgorithmStatus.latest` is never cleared after a successful write.
    - `LessonPanel.kt:191`: the multi-Algorithm offer write runs in a composition scope and can be cancelled partway.
    - `SessionSnapshot.kt:62` stamps `contentRevision` on every `PRACTICE` snapshot, though only LL practice is restored.
    - Attempts filter by wall-clock reset time (`Mastery.kt:38`), while Algorithm Statuses filter by DB epoch (`AlgorithmStatusDao.kt:13`). The wall-clock rule predates Epic 9.
11. **Rejected after re-checking:**
    - **Undo before solving forgives an off-path Move** (`TwoLookSolve.kt:50`). This is intended: the 9.8 residual risks treat Undo as the sanctioned correction, and only a hand correction disqualifies.
    - **A mistyped Algorithm crashes LL practice** (`TwoLookPractice.kt:46`, `AppShell.kt:578`). The 9.2 build-failing verification stops such content from shipping. Generating the scramble from all 78 Algorithms matches the 9.8 spec ("built from random Library Algorithms").
    - **`SessionHost.kt:117` read/write split.** It is reachable only through the internal test constructor.
    - **`LibraryScreen.kt:57` `valueOf`** fails only on a future enum rename, and **`TwoLookMoves.kt:17` unchecked cast** is safe behind `ContentValidator`. Both are speculative.
