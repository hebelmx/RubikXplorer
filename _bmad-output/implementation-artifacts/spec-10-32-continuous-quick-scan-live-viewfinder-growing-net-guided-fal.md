## Intent

**Problem:** Story 10.32 (Epic 10, "Scan my cube"). The continuous facelet mapper (Story 10.30) and the LiteRT sticker-centre detector (Story 10.31) exist, but Quick Scan on the Solve tab still opens the parked 2-corner screen, so a Learner cannot turn the cube in front of the camera and watch the 6-face map fill in.

**Approach:** Replace the 2-corner Quick Scan phase of `GuidedScanActivity` with a `ContinuousQuickScanScreen` driven by the continuous pipeline through an optional base-side port, reuse the existing Guided Scan, Scan Review, per-face retake and `ScanOutcome` paths for every exit, and remove the Quick-Scan-only 2-corner code within the scope the product owner (PO) fixed.

Refs (binding, copied from the story): FR-22, FR-23, FR-25 · NFR-7, NFR-10, NFR-11 · AD-3, AD-9, AD-13, AD-17, AD-18 · UX-DR15, UX-DR16, UX-DR19 · Stories 10.3, 10.15, 10.16, 10.17. No deviation from AD-3, AD-9, AD-13, AD-17 or AD-18 is planned or known; if implementation finds one, it is a blocker to raise, never a residual risk.

**Addition (PO clarification Q8 after the first hands-on device test, 2026-11-25):** A Learner whose scan stalls with most of the cube mapped has no way to finish it by hand without leaving the scan. Add a *Review and Correct* action to the continuous screen that opens the existing Scan Review before the scan is complete; the Learner fills and corrects stickers there and *Accept* finishes the scan. This is one-way: corrections live only inside that Review and never enter the live scan. Everything already described and implemented in this spec stays. The earlier Q8 answers "Latest read, marked as suspect" and "Back keeps the corrections" are withdrawn. The same binding identifiers apply (AD-3, AD-9, AD-13, AD-17, AD-18); no deviation is planned or known.

## Boundaries & Constraints

**Always:**
- AD-3: the scan flow only returns a `ScanOutcome`; the Solve tab's caller dispatches it. No ViewModel or composable mutates session state.
- AD-9 / AD-18: all camera code stays in `app/src/camera/`. Base camera code (`app/src/camera/kotlin`) never references `dev.cubentia.app.camera.continuous.*`; it reaches the pipeline only through an optional Hilt port (`@BindsOptionalOf`), so a variant with `QUICK_SCAN` OFF and another camera flag on still compiles. `QUICK_SCAN` stays `BETA` in debug and `OFF` in release; with it OFF no Quick Scan UI shows.
- AD-13: frames stay in memory on the analyzer thread; nothing is stored, logged or sent. No new permission.
- AD-17: stickers in the net use the shared `StickerAppearance` glyphs; the screen fits a phone in portrait without scrolling and at 200% font on 600 dp width; from the medium window width class (600 dp, the same rule as the Guided viewfinder) and in any landscape window the preview is left and the panel right.
- All Learner text comes from `en.json` through `ContentStrings.resolve(Text(key, args))`.
- The mapper and pipeline are single-threaded: every `processFrame`, `reset` and `export` call runs on the analyzer executor.
- Never guess: only stickers the mapper committed are shown, kept or handed on; blanks stay blank.
- **Settled UI behaviour (PO clarifications Q1–Q7 plus items already fixed by the story and UX spec):**
  - *Count:* "Sides mapped: N/6". N is the snapshot's `mappedFacesCount` once `globalAnchored` is true (6 on `Complete`), and 0 before anchoring (Q5 i). Every "mapped faces" rule below uses this displayed N.
  - *Cue line:* exactly the one cue the mapper emits (`ContinuousScanCue.toText()`, the ten shipped `msg.quick-scan.continuous.*` keys); no cue copy or priority is changed.
  - *Net (Q4 i–iii):* compact URFDLB net; a committed sticker appears at once with no animation; an unread sticker is the blank dark well the Scan Review uses, without the "?" glyph; conflicted stickers get the shared `sticker-highlight` outline (never red), on the net only.
  - *Face outlines (Q4 iv):* one `sticker-highlight` stroke per tracked face, no cell grid; each corner eases half the distance to the newest detection per frame; an outline is removed when its face has not been tracked for 3 frames.
  - *Haptics (Q4 v):* a light tick each time N goes up; a confirm pulse when all 54 stickers are verified; a distinct (reject-style) pulse when the cue becomes a conflict face or a layer twist. Each fires once per transition, and only when the app's haptics setting is on (`LocalHaptics`). No sound, no first-use hint.
  - *TalkBack (Q6):* one polite live region for the cue line, re-announced only when the cue text changes; "Sides mapped: N/6" announced politely each time N increases and never when it falls; nothing assertive. The net is not read sticker by sticker.
  - *Completion (Q1 b):* on the first `Complete` snapshot the analysis stops, the completed net and "All 54 stickers verified." stay for 1000 ms (controls still work), then Scan Review opens automatically. *Reset* during that second cancels the hand-off.
  - *Reset (Q2):* clears the map at once with no confirmation, also with N ≥ 1; the torch stays as the Learner set it; an open twist latch is cleared.
  - *Layer twist (Q3 a):* the net is kept as it was, the twist cue shows, and the screen waits for *Reset*, drawn as the emphasised (filled) action while the twist is latched. *Scan face by face* and *Enter colors instead* still carry the faces confirmed before the twist.
  - *Torch:* shown only when the camera reports a flash unit; OFF when the screen opens; turned off on hand-over to Guided or Review, on leaving and in the background; it stays off on return until the Learner turns it on again.
  - *Close / system Back:* leaves at once (`ScanOutcome.Cancelled`) at N = 0; at N ≥ 1 shows the existing dialog (`msg.scan.discard-title`, `btn.scan.discard`, `btn.scan.cancel`).
  - *Enter colors instead:* never asks; at N ≥ 1 returns `FellBackToEditor(handoff.toFallbackStickers())`; at N = 0 returns `FellBackToEditor(null)` (blank Editor with `msg.solve.scan-fell-back`).
  - *Scan face by face (Q5):* always visible and enabled. Guided asks for (1) every face absent from the exported hand-off — all six before anchoring; and (2) at any number of mapped sides, while the scan is not complete, every face holding conflicted or still-unread stickers, so only faces whose nine stickers the mapper committed are kept (when none is unread, the face the conflict cue names). Kept faces are never reclassified. Back from that Guided viewfinder returns to Quick Scan with the map intact (faces captured in Guided are dropped, as in Story 10.17); *Close* there asks "Discard this scan?".
  - *Review:* the existing Scan Review with per-face retake, suspect ranking and Paint mode; its existing close, accept and calibration-offer rules are unchanged.
  - *BETA label:* only on the Solve tab's Quick Scan button, none inside the screen. *Rotation:* no orientation lock; the map survives a rotation.
  - *Review and Correct (Q8, added 2026-11-25):*
    - *Label, style, place:* one more action on the continuous screen, labelled "Review and Correct" (from `en.json`), the same label in every state. It is an ordinary outlined action, never the emphasised one (under a latched twist that stays *Reset*), placed between *Scan face by face* and *Enter colors instead*.
    - *Availability:* shown only while the displayed N is more than half of the 6 sides AND the stickers set in the shown net (the snapshot's `committedCount`, the number the "… of 54" cue shows) are more than half of 54 — today N ≥ 4 and at least 28 stickers. Both limits are named parameters held in one place (two fractions, 0.5 each, compared with "more than"), not literals spread through the code. When the limits are not met the action is hidden, not shown disabled, and it hides again if either number falls back. It appears and disappears at once: no animation, haptic, sound, hint or TalkBack announcement (Q4 and Q6 list the only ones). It stays available while a layer twist is latched (judged on the kept net). It is hidden for the whole completion hold (snapshot `Complete`), because Review opens by itself then.
    - *Tap:* analysis stops, the torch goes off (as on every hand-over to Review) and the existing Scan Review opens on a fresh export: stickers the mapper confirmed as read, every unread sticker blank, every conflicted sticker blank like an unread one, nothing guessed. If that fresh export is already `Complete`, the Review opens as the completed scan's Review (the *Completion* and *Review* rules above).
    - *Conflicted first (Question 5 c):* the conflicted stickers are ranked first among the stickers to check: the Review opens with the first conflicted sticker selected, and setting a colour moves the selection to the next conflicted sticker that is still blank before any other blank. No mark tells them from unread stickers.
    - *Inside this early Review:* per-face retake, suspect ranking, Paint mode, *Enter colors instead*, the calibration offer and every accept/validity rule are the existing ones. *Accept* finishes the scan exactly as after a completed scan (`ScanOutcome.Accepted` to the Solve tab).
    - *Back (system Back):* returns at once, with no question, to the live continuous scan with the camera-built map, the count and any latched twist as they were when the action was tapped; the torch stays off; scanning goes on as before (under a latched twist the screen still waits for *Reset*). Nothing done in the Review is kept: colours set there and per-face retakes made there are dropped (Story 10.17 rule; Question 7) and are kept only through *Accept*. Opening the action again shows the camera-built map without them. Back keeps its existing closer meanings first: it closes an open discard question, leaves retake mode, leaves a retake viewfinder for this Review, and leaves a calibration opened from this Review.
    - *Close:* in this early Review *Close* always asks "Discard this scan?" (the existing dialog), changed or not: *Discard* returns `ScanOutcome.Cancelled`; *Cancel* stays in the Review with its work.
    - The live scan never holds a Learner correction: no change to `ContinuousFaceletMapper`, no correction layer in the screen.
- 2-corner removal scope (Q7): delete `QuickScan.kt` and `QuickScanDiagnosis.kt`; move `QuickScanPlan`, `CenterCheck` and whatever the kept code needs from them (at least `GridReason`) to neutral files in the same package; keep `CornerHold.kt` and `SideLight.kt` trimmed to what Case capture and the fixture recorder use; KEEP `QuickScanClassification.kt`, `exportKotlinStickerReads` and `evaluateQuickScan` with their tests and the 2-corner code they need; keep `CornerLocator` / `CornerReader` / `CornerGuide`.

## Design Notes

- **Why a port and not a new Activity:** Guided hand-over with Back, Review, per-face retake and the `ScanOutcome` encoding all live in `GuidedScanActivity` and its ViewModel. Hosting the continuous phase there reuses them unchanged; the engine port is the only thing that crosses into the `continuous/` source set.
- **Threading:** UI actions that touch the engine (*Reset*, export for hand-over, Enter colors, completion) are posted to the analyzer executor and publish their result back to the ViewModel, as `switchToFaceByFace` does today.
- **Hand-over without `FaceSample`s:** the kept faces are a `ContinuousScanHandoff` (with any face Guided must retake removed from `faces`); Guided's `added` samples plus that hand-off go to `ScanAssembler.assembleHandover`. A retake from a Review that has fewer than six samples relies on `ScanReview.retaken` using the review's evidence centres; cover that path with a test.
- **6/6 but incomplete:** Q5 (ii)(a) retakes the faces holding conflicted stickers. A mapped face can also hold unread, non-conflicted stickers; the same answer is applied to them (the PO rejected "open Review with blanks" and "disable" for this state).
- **Announce on increase only:** the visible count is not a live region; a separate polite node carries the count text and changes only when N rises.
- **Review and Correct — one way (Q8):** the early Review is a normal Review phase carrying a mark that it came from an unfinished scan. Leaving it by Back only switches the phase back to the continuous screen; the engine, the shown `continuous` state and the twist latch are never touched while the Review is open, so "the map as it was" needs no copy and no restore. Colours set in the Review and retakes made there live in that Review phase only and disappear with it.
- **Review and Correct — where the numbers come from:** the action's visibility is decided from the shown snapshot (the displayed N and `committedCount`), so the Learner sees the rule on the numbers on screen. The Review itself is built from the fresh export, like every other exit, so it can be one frame newer than those numbers; nothing is guessed either way. The conflicted stickers come from the shown snapshot's `conflictedSlots`, because the export carries them only as blanks.
- **Review and Correct — the stickers limit today:** the mapper commits non-centre stickers only after it has seen all six centres, so more than 27 stickers is reachable only at 6/6 sides and the sides limit has no effect yet. Both limits are still separate parameters, as the PO asked.
- **Review and Correct — Close:** the completed scan's Review closes to the Editor without asking when nothing was changed. The early Review always asks "Discard this scan?" instead, because the PO fixed that for this Review and it always holds a camera-built map that Close would drop.
- **Review and Correct — known neighbours, not changed here:** a calibration saved from the early Review restarts Quick Scan with an empty map (deferred item 1, the existing rule), and the landscape-phone-at-200%-font question (deferred item 3) now has one more button in the panel; neither is in this addition's scope.
